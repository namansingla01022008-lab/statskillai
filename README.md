## 📌 Executive Summary

**StatSkillAI** is an enterprise-grade, full-stack educational and workforce intelligence ecosystem designed for students, civil servants, and enterprise professionals. 

Traditional learning management systems suffer from static multiple-choice testing, fragmented course catalogs, and an absence of quantifiable feedback loops. StatSkillAI closes this gap through **psychometric AI-adaptive evaluations** across four core competency domains, **automated diagnostic gap calculation**, **dynamically synthesized learning pathways** linked to national accredited repositories (such as SWAYAM, NPTEL, and iGOT Karmayogi), **real-time 1-on-1 human mentorship**, and **institutional workforce analytics**.

## 👥 Multi-Persona User Experience

StatSkillAI delivers dedicated, role-tailored experiences with row-level security and Role-Based Access Control (RBAC):

### 🎓 1. The Learner Experience
* **Adaptive Diagnostics**: Evaluates 4 foundational domains (*Technical*, *Statistical*, *Digital*, and *Behavioural*) with questions that dynamically adjust difficulty (Easy, Medium, Hard) according to learner capability.
* **Empirical Gap Analysis**: Immediate visualization of competency deficits with priority ordering and severity heatmaps.
* **Personalized Learning Pathways**: Automatically tailored progression sequences featuring verified courses from national e-learning portals.
* **Competency Credit Engine**: Completing milestone steps automatically awards competency points back into the learner profile, dynamically closing the skill gap.
* **AI Quiz Studio**: Dynamic quiz generator based on custom syllabus topics or diagnosed gaps, paired with detailed mistake rationales and pedagogical explanations.
* **Career & Opportunity Portal**: Curated opportunities (jobs, internships, fellowships) with one-click application submission and real-time status notifications.
* **Live Mentorship**: Direct connection to assigned domain mentors with real-time WebSocket messaging and typing indicators.
* **Floating AI Companion**: Context-aware AI assistant accessible across learner screens for instant query resolution.

### 🧑‍🏫 2. The Mentor Experience
* **Mentee Portfolio Management**: Real-time overview of assigned mentees, their target roles, and aggregate progress.
* **In-Depth Diagnostic Review**: Inspect mentee gap analyses, recent assessment attempts, domain radars, and completed milestones.
* **Directives & Path Intervention**: Inject mentor-recommended learning directives directly into a mentee's active learning path, preserved even when AI pathways are regenerated.
* **Real-Time Communication**: Integrated messaging suite with unread counters and live socket connectivity.

### 🏛️ 3. The Institutional Administrator & Leader Experience
* **Unified Workforce Analytics**: Comprehensive institutional dashboard displaying departmental competency distributions, skill-deficit heatmaps, and readiness ratios.
* **AI-Generated Policy Advisories**: Executive summaries and strategic recommendations synthesized directly by Google Gemini.
* **Curriculum & Opportunity Governance**: Publish, edit, and organize accredited courses and career opportunities.
* **Applicant Tracking System (ATS)**: Manage applicant pipelines across review stages (*Submitted*, *Under Review*, *Shortlisted*, *Offered*, *Rejected*), immediately notifying applicants via WebSockets.
* **Mentor Directory Management**: Verify, activate, and manage institutional mentors and allocations.

* **Runtime**: Node.js with `tsx` execution engine

* **Database & ORM**: PostgreSQL via Prisma ORM (17 relational models)
* **Real-Time Engine**: Socket.io server with JWT authentication and room management
* **Artificial Intelligence**: Google Gemini API (`@google/genai`) for adaptive question generation, pathway synthesis, and analytical insights
* **Security & Hardening**:
  * `bcryptjs` (12 salt rounds for cryptographic password hashing)
  * Dual-Token JWT (7-day signed Access Token + 30-day Refresh Token)
  * Secure `HttpOnly` cookie and `Bearer` header authentication
  * `helmet` HTTP security headers
  * `express-rate-limit` endpoint throttling

## 🚀 Getting Started

### Prerequisites
* **Node.js**: v18.0.0 or higher
* **npm**: v9.0.0 or higher
* **PostgreSQL**: v14.0 or higher (local instance or cloud database such as Supabase / Neon / Render)
* **Google Gemini API Key**: Obtainable from [Google AI Studio](https://aistudio.google.com/)

---

### Step-by-Step Installation

#### 1. Clone the Repository
```bash
git clone https://github.com/your-username/statskillai.git
cd statskillai
```

#### 2. Install Dependencies
```bash
npm install
```

#### 3. Configure Environment Variables
Create a `.env` file in the project root:

```env
# Server Configuration
PORT=3000

# Database Connection (PostgreSQL)
# Format: postgresql://<USER>:<PASSWORD>@<HOST>:<PORT>/<DATABASE>?schema=public
DATABASE_URL="postgresql://postgres:your_password@localhost:5432/statskillai?schema=public"

# Cryptographic Token Secrets (Use strong, randomly generated keys in production)
JWT_SECRET="your_jwt_access_secret_key_minimum_32_characters"
JWT_REFRESH_SECRET="your_jwt_refresh_secret_key_minimum_32_characters"

# Google Gemini API
GEMINI_API_KEY="your_google_gemini_api_key_here"

# Client Base URL (Leave blank for local development same-origin proxy)
VITE_API_BASE_URL=""
```

> **Security Notice**: Never commit real database credentials, JWT secrets, or production API keys to version control. Keep `.env` included in your `.gitignore`.

#### 4. Initialize Database Schema & Seed Data
Generate the Prisma client, push tables to PostgreSQL, and seed the demo dataset:

```bash
# Push schema migrations to the database
npm run prisma:push

# Populate database with demo users, organizations, courses & assessments
npm run prisma:seed
```

#### 5. Launch the Development Server
```bash
npm run dev
```

The application will start locally at `http://localhost:3000`.

## 📶 Offline Mode & Resilient Architecture (PWA)

StatSkillAI is engineered for intermittent and unreliable connectivity (supporting **2 to 3 days fully offline** without page crashes or data loss). Built using Progressive Web App standards (`vite-plugin-pwa` + Workbox) and high-performance IndexedDB client storage (`idb`), learners in remote or low-bandwidth environments can continue their educational progress seamlessly.

### Client Storage & Two-Store Model
* **`cache` Store**: Read-only local snapshots of display name/role, active learning path, latest competency gap diagnosis, course catalog metadata, and preloaded assessment question sets. All cached records carry a `cachedAt` timestamp and automatically expire after **7 days**.
* **`outbox` Store**: An append-only persistent queue for offline mutations (`STEP_COMPLETE` and `ASSESSMENT_SUBMIT`). Synced in FIFO order upon reconnection.

### Feature Availability Matrix

| Feature | Offline Status | Behavioral Details |
| :--- | :---: | :--- |
| **App Shell & Cached Pages** | ✅ Available | Service worker precaches HTML/JS/CSS assets. Routes show a "Last updated" timestamp. |
| **Learning Path Milestones** | ✅ Available | Learners can mark steps as completed offline. Actions are queued as `STEP_COMPLETE` mutations in the IndexedDB outbox. |
| **Offline Diagnostic Assessment** | ✅ Available | Preloaded questions (text and choices only) can be attempted offline. Results display: *"Answers saved. Results will be available after you reconnect."* |
| **Course & Opportunity Catalog** | ✅ Available (Read-Only) | Browse cached government and university courses and career listings. |
| **AI Companion & Quiz Generation** | 🚫 Disabled | Google Gemini generative endpoints require cloud connectivity. UI displays a helpful notice and points to preloaded assessments. |
| **Gap Analysis AI Recalculation** | 🚫 Disabled | Server-authoritative gap diagnosis is recomputed upon reconnection and mutation sync. |
| **Opportunity Applications** | 🚫 Disabled | Sovereign job and fellowship applications require real-time verification and are disabled offline. |
| **Mentor Directives & Approvals** | 🚫 Disabled | Mentor workspace allows read-only evaluation of cached mentee profiles; directive transmission and course recommendations require connectivity. |
| **Live Mentor Messaging** | ⏸️ Paused | WebSocket connection status shows as disconnected. Message input is paused to prevent stale or duplicated sends. |
| **Admin Operations** | 🚫 Disabled | Institutional catalog governance and mentor verification toggles are disabled offline with clear warning banners. |

### Zero-Trust Offline Assessment Security
1. **Zero Client Leakage**: The preloaded question endpoint (`GET /api/offline/questions`) strips correct answers, answer indices, answer hashes, and explanations. Only question text and option strings are ever transmitted or cached.
2. **Server-Authoritative Re-Scoring**: Offline attempts are submitted to `POST /api/offline/sync` with answer choices and timestamps. The server evaluates each question against its authoritative answer key in `server/services/questionBank.ts`. **The server never trusts or accepts client-provided scores.**
3. **Anti-Tamper Sanity Checks**: The backend rejects attempts with future submission timestamps, attempts older than 7 days, implausible speeds (<1 second average per question), or unrecognized question IDs.
4. **Strict Idempotency**: Each mutation carries a unique UUID `mutationId` and `attemptId`. Replayed requests return the original server-calculated score without duplicate database records or inflated scores.
5. **Monotonicity**: Milestone step completions are strictly monotonic (`Completed` is never reverted to an earlier state by stale offline clients).
6. **Zero Sensitive Data Storage**: Authentication JWT tokens and passwords are **never** stored in IndexedDB. On user logout or upon detecting an account switch, the entire IndexedDB database and service worker Cache Storage are immediately purged.

## 🛡️ Security Architecture

* **Zero Plaintext Credentials**: All passwords hashed using `bcrypt` with 12 computational rounds.
* **Dual-Token Architecture**: Short-lived Access Tokens (7 days) coupled with long-lived Refresh Tokens (30 days) stored in secure, `HttpOnly`, `SameSite` cookies to prevent XSS exfiltration.
* **Tenant-Level Data Isolation**: Server middleware enforces user ownership and role checks on all mutations (`/api/assessments`, `/api/paths`, `/api/mentorship`, etc.).
* **API Rate Limiting**: Throttles brute-force attempts on authentication routes and protects Gemini proxy endpoints from abuse.
* **Security Headers**: Hardened with HTTP headers via `helmet` including frame protection and content security measures.
